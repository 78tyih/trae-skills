03 · ANTI-SCAM VERIFIER

反诈骗查链 · 公开账本是唯一事实源On-chain verifier · the ledger is the only source of truth

截图、共享屏幕、绿色 Success、格式正确的 64 位哈希——都只是「对方展示的信息」。核验只回答一个可独立验证的问题：这笔交易是否真实存在且字段自洽。Screenshots, screen-shares, green checkmarks, well-formed hashes — all just "claimed info". Verification answers one checkable question: does the transaction exist on the public ledger, self-consistently?

已知锚点Anchor最短核验路径Shortest verification path
TxHash一步反推全字段：Block / Time / From / To / AmountDerive everything: block, time, from, to, amount
Block + Time验证两者是否自洽Check the two are self-consistent
Time反推该时刻真实区块高度Derive the real block height at that time
To + Time扫描真实收款地址在该窗口内的入账Scan the real recipient's inbound in that window
Address + Amount筛候选交易，再以时间窗 / Token / 地址消歧Filter candidates, then disambiguate

「两项足够」不是数学保证——组合可能对应多笔交易，此时必须加条件继续缩小范围。本技能只做技术核验，不做人身定性。"Two anchors suffice" is not a guarantee — combinations can match multiple transfers; keep narrowing. Technical verification only.

04 · FOUR QUESTIONS

四问速览Four questions

解决什么问题Problem
Agent 拿到模糊需求就开干，返工率高；用户拿「转账截图」当事实；视频拆解凭感觉；画图只会一种图型。四个技能把四种直觉冲动各换成一条硬流程。Agents dive into vague briefs; users trust screenshots; video takes get gut-feel scores; everything becomes a flowchart. Four skills replace four instincts with hard processes.
什么场景，什么结果Scenario → Outcome
「我有个模糊想法」→ 5 轮澄清 + 明确分支（上面可演示）；「对方说转了 USDT」→ 链上字段核验；「这个博主值得追吗」→ 带证据链的 Knowledge Score 与 Watch Verdict。"I have an idea" → 5 rounds + a clear route (demo above); "they sent USDT" → ledger verification; "is this creator worth following" → evidence-backed Knowledge Score.
什么结构Architecture
每技能 = 目录 + SKILL.md。grill 与查链是本仓库完整实现；creator / visual 两个是 canonical 规范的 Trae 触发入口（指向 sera-opc-os 与 SeraContextHub），不在本仓库复刻协议，避免双源漂移。Each skill = folder + SKILL.md. Grill and verifier are fully implemented here; creator/visual are Trae entry points to canonical specs (sera-opc-os, SeraContextHub) — deliberately not forked to avoid dual-source drift.
