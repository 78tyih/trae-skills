# Grill Decision Tree — 想法澄清与任务执行决策树

## 工作流概览

```
模糊想法 → grill-me(分轮提问与决策确认) → 共享理解 → 三选一分支
```

## 阶段一：grill-me（苏格拉底式多轮提问）

收到模糊想法/需求后，按顺序执行 5 轮提问，每轮只问一个问题，等待用户回答后再进入下一轮。

### 第1轮：目标澄清
> "你想解决什么具体问题？期望达到什么效果？"

### 第2轮：边界确认
> "这个问题的范围是什么？怎么判断做完了/做好了？（成功标准）"

### 第3轮：约束识别
> "有什么限制条件？时间、资源、技术栈、或其它约束？"

### 第4轮：方案预判
> "你目前有什么想法或倾向的方案？"

### 第5轮：决策确认
> 总结前 4 轮的理解，向用户确认方向是否正确。

## 阶段二：共享理解

将 grill-me 的输出整理为结构化摘要：

```markdown
## 共享理解摘要

**目标**: <用户想要解决的核心问题>
**范围**: <边界和成功标准>
**约束**: <时间、资源、技术限制>
**倾向方案**: <用户的初步想法>
**任务类型**: <由 Agent 判断：简单/技术实现/复杂项目>
```

确认用户认可后，进入分支选择。

## 阶段三：分支路由

根据共享理解中的任务类型，自动选择对应分支：

### 分支1：单独结束 — 一次性澄清任务

**适用条件**：问题边界清晰，答案即解决，无需代码或持续跟进。

**执行流程**：
1. 直接给出答案或方案
2. 确认用户理解
3. 闭环结束

**输出产物**：明确的答案/方案

---

### 分支2：mattpocock/skills — 规格→实现→测试→Code Review

**适用条件**：技术实现类任务，需代码质量保障。

**执行流程**：

1. **规格（Spec）**：编写技术规格文档，明确输入/输出/接口/边界条件
2. **实现（Implement）**：按规格编写代码
3. **测试（Test）**：编写并运行测试，验证规格中的每个条件
4. **Code Review**：审查代码质量、一致性、可维护性

**输出产物**：`spec.md` + 代码 + 测试报告 + 审查记录

---

### 分支3：Superpowers — 设计→计划→执行→验证

**适用条件**：系统性、跨职能、长周期项目，需验证 ROI。

**执行流程**：

1. **设计（Design）**：输出设计文档，包含架构、方案对比、技术选型
2. **计划（Plan）**：拆解任务、排期、里程碑
3. **执行（Execute）**：按计划实施
4. **验证（Verify）**：对照成功标准验证结果，输出验证报告

**输出产物**：设计文档 + 实施计划 + 执行结果 + 验证报告

## 分支选择速查表

| 特征 | 分支 | 判断依据 |
|------|------|----------|
| 问题边界清晰，答案即解决 | 分支1 单独结束 | 一次性回答即可闭环 |
| 技术实现，需代码质量 | 分支2 mattpocock/skills | 需写代码、测试、审查 |
| 跨职能、长周期、需验证 | 分支3 Superpowers | 需完整项目管理和验证 |

## 注意事项

- grill-me 阶段必须按顺序完成 5 轮，不可跳过
- 每轮只问一个问题，等待用户回答后再继续
- 分支选择后严格按照对应流程执行，不混用
- 如果执行过程中发现分支选择错误，回到阶段二重新确认
